# 四轮执行

字段及输入 JSON 以 [handoff contract](handoff_contract.md) 为唯一规范；以下说明科学工作和交互职责，不重复维护一份 schema。 当前交接只保留会影响执行、解释、授权或下一步的事实；实质变更按该合同先记本地 history.jsonl 或既有等效历史，再提炼本次变化原位更新，不追加轮次日记。此路径仅用于研究者要求启动或继续四轮综述证据工作。变更附件及按需参数附件沿当前工作区治理。命令中的 `<研究目录>`、`<当前会话标识>` 等均须替换为实际值。使用当前环境的 Python，并以技能实际位置定位 `scripts/rra.py`。资料和图表的本地文件引用也须使用绝对路径。

## Round 1 — Research Question Elicitation

RQE的核心是 **Evidence-grounded Scientific Problematization and Reasoning**，寻找能够改变读者科学认识的问题，而非未被综述覆盖的关键词组合。以下是可循环的内部认知操作，不是新增外部轮次，也不要求输出内部思考记录：

- 识别认知张力：重建主流解释及默认假设，核查异常是否真实；先区分样本、测量、模型、人群、时间与研究设计差异，并查最近高质量综述是否已解决。
- 形成竞争解释：比较不同模型，按问题使用时间、空间、跨尺度或反事实推理；明确直接证据、间接证据与推测，不把跨论文关联写成既定机制。
- 对抗与修订：主动寻找各重要解释的最强反例和可区分模型的关键证据；不支持时修订、放弃或重构问题。
- 形成科学贡献：明确问题、既有综述的不足与预期认知增量，保留研究者判断。

Assumption Decomposition、Anomaly Exploration、Competing Explanations、Temporal / Multiscale / Counterfactual Reasoning 和 Epistemic Gain Evaluation 是灵活使用的能力，不是必须逐项作答的问卷。对研究者只展示必要证据、关键解释差异及当前需要决定的问题。

新目录用 `init <研究目录> --id <项目标识> --domain <宽泛主题> --session <当前会话标识>` 初始化。先理解主题、现象与边界，用现有检索工具做小规模探索，展示有出处的主要认识、代表性支持／反对证据、相关综述范围和待解释矛盾。明确这是探索，不能称为系统检索；用 `acquire` 登记实际来源、用途和原始凭据，使来源表从 Round 1 即连续维护。

保留现有11项问题池；原实现使用下列语义键，没有额外编号接口。先给出当前证据和竞争解释，再选择最能推进科学判断的一个核心反问，不按固定题数完成，不机械执行问卷：

| 需要澄清的内容 | 可用反问 | `question --uncertainty` |
| --- | --- | --- |
| 现象 | 最希望解释清楚什么现象？ | `phenomenon` |
| 主流解释 | 常见解释的哪部分不充分？ | `explanation` |
| 科学联系 | 可能忽略了什么机制或过程？ | `mechanism` |
| 可检验预测 | 若解释成立，还应解释哪些现象？ | `prediction` |
| 可推翻性 | 什么证据可能推翻这个判断？ | `falsifier` |
| 支持层级 | 直接与间接证据分别支持什么？ | `evidence` |
| 分歧来源 | 是解释冲突，还是条件不同？ | `conflict` |
| 排除边界 | 哪些内容应排除？ | `scope` |
| 读者认识 | 希望读者改变哪种认识？ | `contribution` |
| 科学主线 | 哪条主线最适合组织证据？ | `thread` |
| 既有综述 | 最接近的综述为什么不能替代本工作？ | `overlap` |

`question` 提供追问支架，Codex 应结合当前证据组织本次实际提问。研究者不知道答案时，提供有出处的两三种解释，分别注明证据与假说，允许其选择、批判或提出其他解释。无法支撑某解释时就说明证据缺失，不补造引用。允许研究者回答“不确定”，由Codex继续定向检索；回答改变问题方向时调整探索，不连续追问缺乏信息价值的常规问题。

用最近高质量综述作基线回答：读者已读过它，再读拟写综述，其科学认识会发生什么实质变化？整合机制、解释矛盾、揭示框架局限、重组时间／组织／尺度证据、界定适用边界或提出可检验解释都可形成贡献；仅“更新、更多、更广、题目不同”不能证明高创新性。

问题成熟后给出科学上不同的 A/B/C：A最贴近原始兴趣，B证据基础最充分，C有不同解释视角及潜在贡献。每个候选给出英文暂定题目、问题、范围、贡献、风险、最近真实综述、认知张力、竞争解释、最强反证及认知增量。依据不足的方向标为tentative或unsupported，不能包装成成熟选题。尚无足够强问题时，用空options加assessment和next_search保存当前不足及下一步探索，停留Round 1；不为凑齐三个虚假高创新题目而推进。成熟比较仍提供三个方向，说明推荐理由，由研究者选择或修改。

用 `propose <研究目录> --input <候选JSON>` 保存；收到真实选择后用 `select <研究目录> --choice <候选ID> --confirmation <必要确认原话>` 锁定。仅viable方向可锁定；选定后的 `rqe_summary` 简洁保留科学张力及依据、竞争解释和最强反证、重叠风险、认知增量与检索目标。此处题目仍为暂定，不生成最终论文大纲；题目沿用简洁、学术化的Anchor风格。输出同一交接文件，并提示下一轮在新聊天开始。

## Round 2 — Evidence Acquisition

在新真实会话读交接后，执行 `start <研究目录> --round 2 --session <当前会话标识>`。以已锁定核心问题设计实际检索，覆盖直接原始研究、机制、形态／影像／临床／实验、冲突与反证、相关综述，以及科学／结构 Anchor。按主题选择可用数据库和工具，不强制所有论文包含题目全部关键词；允许机制、表型、实验技术和概念路径。

实际执行检索并记录唯一Search ID、真实时间及明确时区、数据库与平台、原样完整检索式、实际限制、页面命中与实际取得／导入量、原始导出位置及状态。保留布尔运算符、字段限制、主题词和通配符；API、引文追溯、手工或Anchor检索保留真实方式。命中总数不等于实际取回、筛选或纳入数量。浏览工具／Undermind 的原始响应先按规范化合同转换，再交给 `acquire`；脚本不替代模型完成初筛或判断研究结论。对未取回的分页、数据库或全文明确留空并说明。新检索使用新ID追加；同一数据库同一检索式重跑亦不覆盖旧时间、检索式、命中及原始记录。`acquire` 更新同一证据索引并重建独立来源表，不能凭LLM印象填实际数量。

按 [integration的Zotero建库](integration.md#zotero-建库) 检查新鲜本地API、授权及MCP后端，优先沿用已验证writer与集合。原CLI的Web原型仍需 `ZOTERO_API_KEY` 与 `ZOTERO_USER_ID`；已有本地MCP写入不因缺Web凭据而阻塞，不重复建集合。以稳定标识去重，保留真实返回的 item key 与来源；重试先回读现存条目，避免重复导入。只处理本研究集合，保留既有标签，不合并或清理无关旧库记录。归类直接证据、机制支持、间接关联、反证、方法背景和综述／Anchor；待复核与排除条目保留理由。按当前问题定义具体筛选规则，每个排除条目记录阶段和一个主要规则，生成互斥排除计数；“质量低／不相关”本身不构成规则。未取得全文保持待判断，相关但未映射仍为相关，不因反对预设论点而排除。保留同一文献全部Search ID；DOI／PMID等稳定身份辅助去重，无可靠身份则核查题名、作者、年份并保持不确定匹配待核验，不自动把同研究不同报告合并。

分别识别 Scientific Anchor 和 Structural / Stylistic Anchor。同文可兼任，但用途分开说明。前者帮助识别问题、知识与证据链；后者提供实际标题、章节层级、名词短语表达、论证顺序、宏观与局部证据比例。应根据可访问原文提取结构，不能凭标题猜章节。目标学科、综述类型与期刊层级可作匹配依据，影响因子不是唯一依据。

用 `acquire <研究目录> --input <证据清单JSON>` 同步证据；用 `finish-evidence <研究目录> --assessment <为何现有证据足以设计结构及其局限>` 提交有依据的科学充分性判断。未实际检索、没有可用证据或 Collection 未验证时不能完成；无固定篇数下限。服务失败时保留已取回结果；修复当前实际writer的权限／连通性后，Web原型用 `refresh-library <研究目录>` 修复已保存的集合与条目归属，再完成本轮。不得提前锁定正式大纲。

## Round 3 — Argument Architecture

新会话读取交接与证据，执行 `start <研究目录> --round 3 --session <当前会话标识>`。先识别核心科学命题及其支持、解释、冲突和条件关系，区分因果解释与关联，明确关键命题需要的研究类型及尚未闭合的连接。用轻量关系表即可，不建复杂图数据库。

同时展示三套独立的完整标题—大纲组合：A主线最集中，B整合重要竞争解释及证据分歧，C具有证据允许的独特解释路径。每套均有英文标题、一句中心论点、完整一二级标题、每节科学问题、相关命题ID、主要论证路径、与 Anchor 的差异、优点和风险。不能只换标题或章节顺序，也不能默认套用 Introduction → Epidemiology → Etiology → Mechanisms → Clinical Implications → Future Directions。

每套方案同时提供 `capacity`：预计最终映射文献区间、真实候选库与初筛的估计依据、来源Search ID、密集章节、直接证据缺口、过载／不足风险、可调整范围及解释代价。三种方案须有不同科学论证重心，不能变成小／中／大篇幅版本。

区分实际取得的检索候选库、筛选确认的相关证据库与完成具体论证位置映射的最终目录。专题综述默认规划50–250篇去重后的最终映射文献；期刊要求可覆盖默认，系统综述等遵循其既定纳入标准。估计使用实际库、已完成筛选和可解释方法；不确定时给区间并指出未筛部分，无法估计时明确null，不编造精确数字。

预计超过250篇时检查重复证据、外围主题、可独立支线及标题承诺过多问题；少于50篇时区分领域聚焦与检索不足，检查直接证据、过度推测及是否宜改用窄范围综述。解释调整对科学解释的后果，在锁定前完成必要范围协商；有充分理由可超出默认区间，不因数量自动增删文章或忽略反证。控制的是承担的科学问题规模，不引入预测模型、评分公式或多级数量门。

英文标题与各级标题优先学习适合学科的简洁 Anchor：突出科学主题、使用清楚的名词短语，避免塞入所有范围、无必要冒号和并列结构、完整句子式章节名及免责声明式标题。不按硬字符数裁剪，不机械重复“Current evidence and limitations of…”等套话；具体论证由问题和证据决定，不照搬 Anchor 章节或句子。

用 `propose` 保存三个组合。研究者可选、改、合并或要求重生；混合版本整理成单一清晰候选后再次确认。若研究者选择实质不同的范围，`select` 先采用候选 `research_scope`，保留全部文献与历史检索，将筛选统一重置为uncertain并清除旧映射，停留Round 3；随后用 `acquire` 提交与新 `screening_scope` 一致的统一重筛，重新 `propose` 再按原机制选择大纲。单纯超过容量目标不会自动改范围。范围明确后用 `select` 保存必要确认原话，锁定正式英文标题、核心问题、中心论点、完整层级、论证路径及范围／排除边界；未确认不得进入 Round 4。命题的表述、推断类型与所需研究类型同时形成锁定指纹；其后的证据补充不能借机改变这些科学定义。该轮更新同一交接，结束当前会话。

## Round 4 — Paragraph-Level Evidence Mapping

新会话仅从 Round 3 的规范交接进入，执行 `start <研究目录> --round 4 --session <当前会话标识>`。按已锁定各节重新审查证据。需要时读取摘要、全文、图表与补充，抽取对象、样本、设计、关键方法、相关结果、适用条件及推断限制；保持原始研究和综述转述的来源区别。

为各节建立有科学功能的段落序列。每段给出中心命题、段落功能、具体研究结果及其 Zotero 标识、论证路径和与下一段的关系；有实际冲突或限制才补充相应说明，不强制无意义字段。论证路径用简洁计划表达，不提前写成完整正文。允许一文多段、一段多文。

映射后用唯一文献ID重新计算最终总数、主要章节文献数、相关未映射数、重复引用及核心直接证据缺口，更新 `capacity_review` 和来源表。跨段或跨节引用同文，全局仅计一次；各来源计数可能交叉，不能相加当全局总数。检查命题与结果是否匹配、重复引用是否合理、原始样本是否重复计数，以及某节缺证据或证据过度集中。引用冗余可在既定范围内精简；没有可靠证据的命题明确留作缺口。若需删核心章节、改变科学问题或实质调整标题承诺，返回Round 3与研究者协商。重大反证或需要更换已锁定主线时，用 `issue <研究目录> --message <问题及影响>` 保存当前问题，向研究者提出局部修订，取得明确确认后回到适当上游轮次处理，不静默改写锁定结构。

精读得到的资料、结果定位及命题证据引用可更新同一 `rra_v6_evidence.json`，随后必须重新 `map` 校验；已锁定命题的表述、推断类型或所需研究类型变化须先 `issue`、取得研究者确认，再 `reopen` 上游选择。`mapping_lock` 绑定当前命题引用、文献结果和段落；映射后任一项改变均需重新 `map` 才能导出。Round 4 已完成也可在原批准大纲下重新映射，不必重选科学结构。

使用 `map <研究目录> --input <段落映射JSON>` 保存，再依 [Anchor Refine contract](writing_input_contract.md) 检查 primary structural anchor 的可访问全文、科学事实计划及预期图表；若无预期图表，须有明确范围声明。以 `export <研究目录>` 输出 `anchor_refine_input.md`，其中仅有锁定结构、段落计划、证据映射、两类 Anchor、可用资料、冲突与过度推断边界，并引用同一来源表。后续内部写作模块新增引用继续登记来源与映射位置，不另建日志或文献库。

## 失败与恢复

- 交接不存在：新研究从 Round 1 初始化；已有研究检查目录，不生成假上游。
- 阶段不匹配：依当前状态继续，不跳过选题或大纲确认；跨轮必须新聊天，同一未完成轮可在新聊天用 `start --round <当前轮次> --session <新会话>` 恢复。
- 检索未完成或证据不存在：保存实际结果及缺口，继续有针对性的证据工作，不把计划当回执。
- Collection失效：`start` 仅只读核查；显式执行 `refresh-library <研究目录>` 才修复归属或在已删除时重建专属集合，并查看返回结果。它保留科学选择、使旧派生映射／写作计划失效，已有段落需重新 `map`。
- Anchor不可访问：说明受影响的是科学解释还是结构分析，寻找真实可用替代；不伪造全文分析。
- 研究者未选择：停留相应阶段，只继续不依赖该选择的工作。
- 新证据推翻论点：保留现有锁定合同，明确呈现修订及科学影响，等待研究者确认。

`status` 报告实际状态。`fixture_complete` 只说明模拟流程通过；实际完成还要求真实来源、服务回读及真实研究者选择。CLI 状态不能独立证明来源结论正确、系统检索完整、聊天确已切换，或全文写作已获授权。

## 内部写作阶段

获授权的正式写作经[单线程科学作者](writing.md)后进入[双编辑独立提议及互核](language_editing.md)。研究规划沿用四轮会话与既有存储身份。

Round 4 导出的 Markdown 供证据映射使用。新表达方案使用作者可编辑的离线 HTML，沿用已有项目已批准计划。获真实写作授权后进入本技能的 [INITIAL / ITERATE](writing.md)，保持实际动态引用及唯一权威 DOCX。旧项目的 `next_round:anchor-refine` 和 `writing` 均表示此入口。规划和正文的完成状态分别检查。
